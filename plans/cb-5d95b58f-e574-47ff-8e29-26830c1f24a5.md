## Implementation units

### U1: `deploy.yml` triggers and header comment

1. Replace lines 4–32 (the `push:` block) with exactly:

   ```yaml
   push:
     tags:
       - "v*"
   ```

   Use the block-list form `deploy-docker-tag.yml` already uses. It parses to `{tags: ["v*"]}`. Add no `branches`,
   `branches-ignore`, `tags-ignore`, `paths` or `paths-ignore` key.

2. Leave `pull_request` (lines 33–61) byte-for-byte unchanged. Leave `workflow_dispatch:` unchanged, still with a null
   value.
3. Leave `name`, `permissions` and `jobs` byte-for-byte unchanged. That includes the `Deploy 🚀` step's
   `if: github.event_name != 'pull_request'`.
4. Insert the settled header comment verbatim, as four lines, between `name: Deploy site` and `on:`, with a blank line on
   each side. This matches where `ci.yml` puts its header (after `name`, before `on`). Comments do not change the parsed
   YAML. The text:

   ```yaml
   # This workflow publishes the site when a v* release tag is pushed. The ombee scheduler's
   # cb release tick pushes the tag after Command Center's Deploy now (or cb release request) files
   # a Release issue. A merge to main does not publish. To republish a release by hand, run this
   # workflow from that release's tag.
   ```

   The phrase `publishes the site when a v* release tag is pushed` must stay on one physical line, which is line 1 of the
   comment. All four lines are well under printWidth 150, and Prettier does not rewrap YAML comments.

## Risks

- **Infrastructure change to the public publish path.** A wrong trigger either publishes unreleased commits (if `branches`
  survives) or never publishes (a bad tag pattern). The tag pattern `"v*"` matches cb's `vN.N.N` tags and the
  docker-tag workflow's existing pattern.
- **First tag, Docker job.** Without U2, the first `v*` tag starts `Docker Image CI (Upload Tag)`, and that job fails at
  Docker Hub login (no secrets). U2 makes it skip, as its siblings do.
- **Merge-time publish.** The merge commit of this PR is a push to `main`. With the new trigger it starts no `Deploy site`
  run (AC 7, operator-verified). Before the merge, nothing in this PR can publish.
- **Pages timeout** (as on 2026-08-27). The fix is to re-run that run, per Decisions settled. No retry is added.
- **Public repository.** Comments and the Release notes are public. The settled comment text names only "the ombee
  scheduler", which the issue chose.
