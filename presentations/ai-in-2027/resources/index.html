Start small

Use an approved tool and material you are allowed to share. Do not paste secrets or customer data into an unapproved service. You can move at a pace you can handle.

  • Review: "Read this draft. Identify the weakest argument and point to the sentence that needs work."
  • Think: "Ask me questions about this idea. Help me notice assumptions before suggesting a plan."
  • Understand: "Explain this code path. Link the files you inspected and separate facts from assumptions. Do not change files."
  • Explore: "Propose two architectures. Compare the trade-offs and list the decisions you need from me."
  • Change: "Refactor only this function. Preserve behavior, show the diff and stop if other files need changes."
  • Check: "Generate tests and docs for this small example. Tell me which checks you ran and which you could not run."

For code changes, use test data and a review branch. For a document, work on a copy. You decide whether to accept the result.

Ask for a reviewable artifact

"Create a short walkthrough with the output, changed files or references, decisions and trade-offs, actual check results, uncertainty and the next decision I need to make."

Use an artifact you can open after the chat: a diagram, document, prototype, sample export or code diff. Ask for a decision summary and observable evidence, rather than hidden reasoning. Open the references and check the result yourself.

Claude’s Artifacts help guide [27] explains creating, editing, sharing and exporting work beside a conversation. Treat this as one example of the workflow, not a requirement to use Claude. Inspect sharing settings before publishing anything.

Learnable practices

  • Matt Pocock’s website [24]: educator and engineer; links to his teaching and videos.
  • Matt Pocock’s skills repository [23]: read the grilling and test-driven development examples. Try one practice before installing a collection.
  • Poteto’s pstack in cursor/plugins [25]: Lauren Tan’s collection includes read-only investigation, prototyping and bug-fix playbooks with runtime evidence. It also includes advanced workflows you do not need to adopt.

A skill packages instructions and supporting material for an agent. Read third-party skills before installing them. Compatibility, tool permissions and maintenance vary. Neither collection is a productivity benchmark; this talk makes no PR-count claims.

Audience and speaker versions

The plain deck URL always starts with notes hidden. The speaker link turns them on; the Notes button turns them off again. The setting is in the URL, not stored between visits. Notes are public content, not a private presenter channel.

Print / PDF exports every slide without notes in audience view. Print + notes includes them in speaker view on taller pages. Turn notes off before making an audience PDF. When JavaScript is off, all slides remain readable and speaker notes stay hidden.
